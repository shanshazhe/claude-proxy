Gateway-maintained Project Code Memory

When on, the gateway installs a query-only skill and adds a ProjectMemoryUpdate tool to Claude requests that can edit files. After a code change Claude calls it once and the gateway refreshes, adds and deletes records in the background with a cheaper model (Luna, then Haiku). Requires Claude CLI and Python 3.9+. When both are available and you have never changed this setting, the proxy turns it on at startup and upgrades an unchanged known older deployment after backing it up. Other existing skills stay untouched until you turn this on: they are moved to claude-proxy/skill-backups/ in your Claude CLI directory before installing the query-only skill. Without the dependencies it stays off and cannot be selected. Turning it off removes the skill only if unchanged and stays off; backups and project caches are kept. Claude Code shows one “No such tool available” line per update; this is expected. Open a new Claude session after changing it.

Online Summary

Tool outputs at or above the threshold below (except Read) are summarized by a cheap model before they reach your main model: key facts plus verbatim key lines with line numbers. The full original stays on this computer for Read. Tool outputs are sent to the selected model's provider.

Lower thresholds summarize more outputs and save more tokens, but each summary adds a few seconds.

Session archives in ~/.claude/gateway-observations not used for this long are deleted at proxy start and hourly, even while Online Summary is off. Resuming such a session later sends its earlier tool outputs in full.

Sent to the summary model as its system prompt. Its reply must stay JSON with summary and highlights; otherwise summaries fail and the original output is kept. Reset restores the built-in prompt.
